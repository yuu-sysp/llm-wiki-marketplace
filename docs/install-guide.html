LLM Wiki 導入・更新手順

Claude Code プラグイン llm-wiki を新しいPCに入れる／すでに入っているPCを更新するための手順書。所要 5分。

v0.3.0WindowsPython 3 が必要

どの手順を使うか

A. インストーラ（推奨）

CLI の有無を問わない。vault のフォルダ構成まで作る。

B. Claude Code 内から

最短。フォルダ生成は初回セッションに任せる。

C. デスクトップアプリのみ

CLI が無く、GUI だけで登録する場合。

前提

  • Python 3 が コマンド名 python で起動できること。フックが python を直接呼ぶため、py ランチャーだけの環境では自動蓄積が動かない（インストーラが検出して警告する）。無ければ install.bat -InstallPython で自動導入できる。
  • Claude Code（CLI かデスクトップアプリのどちらか）。プラグイン登録に必要。
  • inbox で pptx / xlsx / docx / pdf を扱うなら変換ライブラリ（インストーラが自動導入。オフライン環境は -NoDocLibs で省略）。

A. インストーラで入れる

  1. リポジトリを取得する

    git clone https://github.com/yuu-sysp/llm-wiki-marketplace.git
cd llm-wiki-marketplace

  2. インストーラを実行し、保存先を選ぶ

    .\install.bat                                  # 保存先はダイアログで選ぶ
.\install.bat -VaultRoot "D:\資料\LLM-Wiki"    # パスを直接指定する場合
.\install.bat -InstallPython                   # Python が無いPC

    選んだフォルダの直下に LLM-Wiki を作る（LLM-Wiki 自体を選んだ場合は二重にしない）。D: など別ドライブも選べる。キャンセルすると中止する（勝手な場所には作らない）。

    確認ログに [OK] Python と [OK] プラグイン登録＋vault_root 設定を確認 が出ること。[!!] コマンド名 python では… が出たら、先にそれを解消する。

  3. Claude Code を完全に終了して起動し直す

    起動済みのセッションには vault_root も環境変数も届かない。デスクトップアプリはタスクトレイに常駐していることがあるので、終了しきること。

    確認ここを飛ばすと、必ず「Vault が未設定」で失敗する。

  4. 動作を確認する

    claude plugin list        # llm-wiki@llm-wiki-marketplace が enabled

    確認Claude Code で /llm-wiki:lint が動けば導入完了。

B. Claude Code 内から入れる

  1. マーケットプレイスを登録してインストールする

    /plugin marketplace add yuu-sysp/llm-wiki-marketplace
/plugin install llm-wiki@llm-wiki-marketplace

  2. vault_root に保存先を入力する

    例: D:\資料\LLM-Wiki / C:\Users\<ユーザー名>\Documents\LLM-Wiki

    確認空のまま Confirm しないこと。空だと skill が vault を解決できず「inbox の場所が解決できない」になる。

  3. Claude Code を再起動する

    フォルダ構成は初回セッションの SessionStart フックが自動生成する。

    確認/llm-wiki:lint が動き、vault に concepts/ notes/ pages/ inbox/ meta/ ができていること。

C. デスクトップアプリだけの場合

  1. プラグイン画面を開く

    プロンプト横の ［＋］→ Plugins（または chat に /plugin と入力）。

  2. Marketplaces タブ → Add marketplace

    次を貼り付ける: https://github.com/yuu-sysp/llm-wiki-marketplace.git

  3. Discover タブ → llm-wiki を Install

    スコープは User。vault_root に保存先を入力して Confirm。

    確認/reload-plugins のあと、/ メニューに /llm-wiki:init などが出ること。

vault（Wiki の保存先）について

D ドライブは必須ではない。パスは次の順で解決する。

優先解決元設定される場所
1スクリプトの第1引数単体実行のときだけ
2CLAUDE_PLUGIN_OPTION_VAULT_ROOTプラグインの vault_root（userConfig）
3LLM_WIKI_VAULT_ROOTインストーラが setx で設定（フォールバック）
設定不要

「いつ・何を・どこへ書くか」の蓄積方針は SessionStart フックが毎セッション自動で配る。利用者が ~\.claude\CLAUDE.md に書く必要はない（書くと、そのPCだけの設定になってしまう）。

更新する（すでに入っているPC）

つまずきやすい点

marketplace update だけではプラグイン本体は更新されない。install も「already installed」で何もしない。plugin update が必要。

コマンド効果
claude plugin marketplace update llm-wiki-marketplaceマーケットプレイス定義を取り直すだけ
claude plugin install llm-wiki@llm-wiki-marketplace導入済みなら何もしない
claude plugin update llm-wiki@llm-wiki-marketplace本体を新しい version へ（要再起動）

  1. 定義を取り直して本体を更新する

    claude plugin marketplace update llm-wiki-marketplace
claude plugin update llm-wiki@llm-wiki-marketplace

    確認updated from <旧> to <新> と Restart to apply changes が出ること。

  2. Claude Code を再起動する

    確認~\.claude\plugins\installed_plugins.json の version と installPath が新しい版に変わっていること。

直したものを配る（発行側）

version を上げないと届かない

プラグインは ~\.claude\plugins\cache\<marketplace>\<plugin>\<version>\ に version 単位で展開される。version が据え置きだと、利用者が更新しても古いコードのまま動き続ける。

  1. version を2箇所とも同じ値に上げる

    plugins/llm-wiki/.claude-plugin/plugin.json と .claude-plugin/marketplace.json。

  2. 発行する

    .\publish.bat "変更内容"     # メッセージは必ずダブルクォートで囲む

    確認version の不一致・上げ忘れは publish.bat が検出して発行を止める。push 後は GitHub Actions（plugin-smoke）が green になること。

困ったとき

症状原因と対処
「Vault が未設定で inbox の場所が解決できない」vault の解決経路が両方空。claude plugin list に居るか確認し、Claude Code を完全終了して再起動する
インストーラは「完了」なのに skill が vault を見つけないCLI が無い環境では登録がスキップされ、vault フォルダだけが作られる。手順 C で vault_root を入力する
蓄積方針が出ない／inbox に当日ファイルができないフックが呼ぶ python が使えない。-InstallPython で導入するか PATH を通す。Microsoft Store のエイリアスが横取りしている場合は「設定 > アプリ > アプリ実行エイリアス」で python.exe を OFF にする
更新したのに古い挙動のまま①plugin update を叩いていない ②発行側が version を上げ忘れている
lint に「inbox 未変換」が出る非 md が残っている。/llm-wiki:ingest が変換する。末尾 / はフォルダなので中のファイルを inbox 直下へ出す。.doc/.xls/.ppt は .docx 等で保存し直す
lint が当日の inbox スタブを挙げる想定内。失敗には数えない（翌日フックが自動で掃除する）
.bat が「指定されたファイルが見つかりません」.bat は ASCII＋CRLF 必須。UTF-8/LF で保存すると cmd.exe が誤動作する

導入後の使い方

  • /llm-wiki:save … 直前の会話の知見をページ化する
  • /llm-wiki:ingest … inbox/ の資料（pptx/xlsx/docx/pdf も可）を取り込む
  • /llm-wiki:query … Wiki を検索して出典付きで答える
  • /llm-wiki:lint … 赤リンク・孤立ページ・inbox 残りを検査し index を再生成する
  • /llm-wiki:init … vault の足場を作り直す（既存ファイルは上書きしない）

普通に開発しているだけで、知見は inbox/{日付}-{プロジェクト名}.md に溜まっていく。区切りで /llm-wiki:ingest を叩けばページになる。
